# KineLab Solo V6.3 Validation Data Policy

This directory governs all data collection, benchmark traces, and telemetry exports associated with **KineLab Solo V6.3** monocular webcam validation.

All contributors, engineers, and automated agents must adhere strictly to these data classification rules.

---

## 1. Permitted Data (May Be Stored)

The following categories of data are explicitly permitted in validation records, diagnostic artifacts, and test logs:

- **System & Hardware Metadata**:
  - Machine hostname, manufacturer model (e.g. `Alienware m18 R2`), CPU architecture, and operating system (`Windows 11`).
  - Video device descriptors (e.g. `Integrated Webcam RGB`), resolution (`width` × `height`), and capture framerate.
  - Browser engine, user-agent string, and WebGL support flags.
- **Deidentified Biomechanical Time-Series**:
  - Discrete joint angles (degrees), angular velocities (°/s), and range-of-motion (ROM) excursions.
  - Raw vs filtered angle comparison deltas (`liveRawAngle` vs `liveFilteredAngle`).
  - Movement trial outcomes, repetition counts, and bilateral symmetry metrics.
- **Pipeline Telemetry & Quality Indicators**:
  - Model inference latency, inference FPS, and frame render FPS.
  - Landmark visibility ratios (e.g. fraction of landmarks with confidence ≥ 0.4).
  - Screen-plane view classification tags (`LEFT_SAGITTAL`, `RIGHT_SAGITTAL`, `FRONTAL`, `SAGITTAL`, `OBLIQUE`).
  - Suspension state flags and reason enums (`WRONG_VIEW`, `PATIENT_TOO_CLOSE`, `PATIENT_TOO_SMALL`, `JOINT_CLIPPED`, `LANDMARK_OCCLUDED`).
  - Automated coaching cue strings (`Move back`, `Turn sideways`, `Keep ankle visible`).
- **Synthetic & Fixture Data**:
  - Algorithmic poses, synthetic walk cycles, and simulated calibration logs.

---

## 2. Strictly Prohibited Data (Must NOT Be Stored)

The following categories of data are **strictly forbidden** from being recorded, committed, exported, or preserved:

- **Raw Video Feeds & Photographic Imagery**:
  - No MP4, WebM, AVI, or uncompressed frame buffers of human subjects.
  - No webcam snapshots, facial images, or background home/office environment photos.
- **Identifiable Biometrics & Facial Embeddings**:
  - No face mesh embeddings, facial recognition encodings, or biometric identifiers.
  - Facial landmarks must not be persisted beyond transient in-memory frame processing.
- **Protected Health Information (PHI) & PII**:
  - No real patient names, social security numbers, medical record numbers, addresses, phone numbers, or dates of birth.
  - Only synthetic identifiers (e.g. `PT-001`) may be utilized.
- **Secrets & Credentials**:
  - No API keys, cloud tokens, private certificates, or local authentication cookies.

---

## 3. Enforcement & Verification

1. All export files generated by `SoloValidationPanel` (via the dev route `?soloValidate=1`) output only deidentified scalar aggregates and numeric arrays compliant with the schema in `artifacts/solo-webcam-v63-validation.json`.
2. Any validation dataset committed to this repository that violates the prohibited data rules must be purged immediately.
